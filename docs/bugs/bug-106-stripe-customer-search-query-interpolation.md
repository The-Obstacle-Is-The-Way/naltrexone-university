# BUG-106: Stripe Customer Search Query Uses String Interpolation

**Status:** Open
**Priority:** P1
**Date:** 2026-02-07

---

## Description

`createStripeCustomer` builds a Stripe Search API query by interpolating `userId` directly into the query string:

```typescript
const query = `metadata['user_id']:'${input.userId}'`;
```

While `userId` is a UUID generated by Clerk and validated upstream, this is not a parameterized query. If a malformed or adversarial `userId` containing single quotes or Stripe Search query syntax were to reach this code, it could alter the search semantics.

**Observed:** User ID is interpolated directly into Stripe Search query string.

**Expected:** Query construction should sanitize or validate the `userId` format before interpolation, or use a parameterized approach if available.

## Steps to Reproduce

1. Call `createStripeCustomer` with a `userId` containing `'` characters
2. Observe the malformed Stripe Search query

## Root Cause

Stripe's Search API does not support parameterized queries. The code assumes `userId` will always be a clean UUID, but does not validate this assumption at the point of use.

## Impact

- Low probability: `userId` comes from Clerk, which generates UUIDs
- Defense-in-depth gap: if any upstream validation is bypassed (e.g., a test, a different auth provider, or a refactor), the query could be injected
- Could return wrong customer results, leading to billing misattribution

## Fix

Add a UUID format assertion before query construction:

```typescript
if (!/^[\w-]+$/.test(input.userId)) {
  throw new ApplicationError('VALIDATION_ERROR', 'Invalid user ID format');
}
```
