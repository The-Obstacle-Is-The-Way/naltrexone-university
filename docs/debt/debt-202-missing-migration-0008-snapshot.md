# DEBT-202: Missing Drizzle Migration 0008 Snapshot File

**Status:** Open
**Priority:** P3
**Date:** 2026-02-09

---

## Description

Migration `0008_attempts_session_question_unique` was manually created for BUG-105 (concurrent answer submission race condition). It contains custom SQL — a CTE that deduplicates historical `(practice_session_id, question_id)` collisions, then creates a partial unique index. Because the migration was hand-written rather than generated by `pnpm db:generate`, no corresponding `0008_snapshot.json` exists in `db/migrations/meta/`.

The `_journal.json` records the migration (idx 8), and `db/schema.ts` correctly defines the index at line 391-393. However, Drizzle uses snapshot files for diffing when generating new migrations. Without snapshot 0008, the next `pnpm db:generate` will diff against snapshot 0007 (which lacks the index) and produce a duplicate migration attempting to create the same `attempts_session_question_uq` index.

## Impact

- Next developer who runs `pnpm db:generate` will get a spurious migration that duplicates the index
- The `IF NOT EXISTS` clause in the original migration prevents runtime failure, but the duplicate migration is confusing
- Drizzle's schema introspection is out of sync with reality

## Files

- `db/migrations/meta/_journal.json` — records migration 0008 (line 61-67)
- `db/migrations/meta/` — missing `0008_snapshot.json`
- `db/migrations/0008_attempts_session_question_unique.sql` — manually written migration
- `db/schema.ts:391-393` — index correctly defined in schema

## Resolution

Manually create `0008_snapshot.json` by copying the previous snapshot and adding the missing index:

1. Copy `db/migrations/meta/0007_snapshot.json` → `db/migrations/meta/0008_snapshot.json`
2. Update the `id` field to a new UUID and set `prevId` to `0007`'s `id` value (`9991b358-8e1c-42bb-a097-eb01e1f08ccf`)
3. Add the `attempts_session_question_uq` index entry to the `public.attempts.indexes` block:
   ```json
   "attempts_session_question_uq": {
     "name": "attempts_session_question_uq",
     "columns": [
       { "expression": "practice_session_id", "isExpression": false, "asc": true, "nulls": "last" },
       { "expression": "question_id", "isExpression": false, "asc": true, "nulls": "last" }
     ],
     "isUnique": true,
     "concurrently": false,
     "method": "btree",
     "with": {},
     "where": "practice_session_id IS NOT NULL"
   }
   ```
4. Verify `pnpm db:generate` produces no new migrations afterward

**Important:** Do NOT run `pnpm db:generate` without the snapshot fix — it will diff against snapshot 0007 (which lacks the index), see the index in `schema.ts`, and generate a duplicate migration attempting to recreate the same index.

## Verification

```bash
ls db/migrations/meta/0008_snapshot.json  # Should exist after fix
pnpm db:generate                          # Should produce "No schema changes" (no new migration)
```
