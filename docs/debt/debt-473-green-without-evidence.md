## Description

A green test signal in this repository currently means one of four different things, and the aggregate signal does not distinguish them:

1. The behavior executed and passed.
2. The behavior was intentionally out of scope for this run.
3. The behavior was **requested and could not run**.
4. The mechanism that was supposed to detect an omission did not detect it.

States 1 and 2 are legitimate. States 3 and 4 are defects, and the tree contains reachable instances of both. Jim Shore's definition is the standard this debt is measured against: "Some people recommend making your software robust by working around problems automatically. This results in the software 'failing slowly.' The program continues working right after an error but fails in strange ways later on. A system that fails fast does exactly the opposite: when a problem occurs, it fails immediately and visibly." ([Shore, *Fail Fast*, IEEE Software, 2004](https://www.martinfowler.com/ieeeSoftware/failFast.pdf)). His worked example is a missing configuration property silently defaulted to `10`; `process.env.STRIPE_SECRET_KEY ?? ''` followed by `describe.skip` is the analogous shape.

The repository already contains two correct implementations of the standard, which is why this is filed as inconsistency rather than as a new design:

- Every one of the 40 database-backed integration files throws at import when `DATABASE_URL` is absent: 35 through `tests/integration/helpers.ts:7-11` (32 directly, three via `tests/integration/bug-regression-test-helpers.ts:9`), one through `tests/shared/resolve-integration-database-url.ts:20-22`, and four through local module guards (`actions.stripe`, `controllers`, `db`, `tag-taxonomy-census`). Representative executions exit 1.
- Both executable Playwright journey projects depend on `setup` (`playwright.config.ts:38-48`); `setup` owns the `cleanup` teardown (`:27-35`). Its single test calls `runE2ECredentialHealthCheck()` (`tests/e2e/global.setup.ts:8-13`) and throws on a missing or dummy credential before any journey spec runs. Every supported entry point (`pnpm test:e2e`, both CI workflows) preserves that dependency; only `playwright test --no-deps`, which nothing in the repository invokes, bypasses it.

The Stripe provider suites, the CI skip-policy step, the required-check shape, and (F10) the local-run wrappers do not follow that standard.

### F1 — Both Stripe provider suites report green when the operator asked them to run and they could not

`tests/integration/stripe-checkout-client-contract.integration.test.ts:11-35` and `tests/integration/stripe-trial-clock-smoke.integration.test.ts:8-32` compute a `skipReason` from three inputs — the opt-in flag, `STRIPE_SECRET_KEY`, and a price ID — and select `describe.skip` whenever any reason exists:

```ts
const skipReason = !RUN_STRIPE_CHECKOUT_CLIENT_CONTRACT
  ? 'set RUN_STRIPE_CHECKOUT_CLIENT_CONTRACT=true to run the external Stripe contract'
  : !isUsableStripeTestKey(stripeSecretKey)
    ? 'provide a real Stripe test secret key'
    : /* price check */ ;
const describeStripeContract = skipReason ? describe.skip : describe;
```

The first branch is correct: the flag is off, the hermetic lane must not touch Stripe, and skipping is the honest result. The second and third branches are not: the operator has stated intent (`RUN_…=true`) and the suite cannot honor it. That is a configuration error, not an absence of scope. Reproduced at `5a095f12` through the canonical entry point, and re-reproduced independently by both later passes:

| Command | Result |
| --- | --- |
| `env -u STRIPE_SECRET_KEY RUN_STRIPE_CHECKOUT_CLIENT_CONTRACT=true pnpm test:integration tests/integration/stripe-checkout-client-contract.integration.test.ts` | exit 0, `Test Files 1 skipped`, `Tests 4 skipped` |
| `env -u STRIPE_SECRET_KEY RUN_STRIPE_TRIAL_CLOCK_SMOKE=true pnpm test:integration tests/integration/stripe-trial-clock-smoke.integration.test.ts` | exit 0, `Test Files 1 skipped`, `Tests 2 skipped` |
| usable `sk_test_` key exported, dummy price, flag on (the review's falsification run) | exit 0, 4 skipped, no Stripe request |

The third row is the important one: the defect is "flag on plus *any* unusable prerequisite selects `describe.skip`," not any single input. Vitest offers no fail-on-skip switch (`vitest run --help` lists only `--hideSkippedTests`, `--passWithNoTests`, and `--allowOnly`), so the only place this can be made correct is the suite's own module scope. The trial-clock file already contains the right shape one function later — `getStripe()` at `:36-39` throws `Stripe trial clock smoke skipped: …` — but it is unreachable because `describe.skip` never invokes it.

### F2 — The only fail-closed guard is a wrapper around one invocation, and the safe path is the hard one

`scripts/run-trial-clock-smoke.ts` is correct and thorough: `assertPreflight` (`:71-90`) rejects a non-`true` flag, a non-`sk_test_`/`dummy` key, and a non-`price_`/`dummy` price; `createTrialClockSmokeInvocation` (`:93-122`) runs exactly the two provider files with both flags injected; `readReporterAssertions` (`:124` onward) rejects a report that is not `success: true`, and `:184-191` rejects any `skipped`/`pending`/`todo`/`disabled` case as `PROOF_SKIPPED`. Verified: `env -u STRIPE_SECRET_KEY RUN_STRIPE_TRIAL_CLOCK_SMOKE=true pnpm exec tsx scripts/run-trial-clock-smoke.ts` exits 1 with `PREFLIGHT_KEY_INVALID`.

But correctness depends on which entry point an operator picks, and the unsafe one is the default:

- `package.json` exposes eight `test*` scripts; none invokes the wrapper. Its only production caller is `.github/workflows/stripe-trial-clock-smoke.yml:46`.
- The wrapper does not load `.env.local`, the documented home of local secrets; the dotenv loaders in the tree are `playwright.config.ts:6`, `drizzle.config.ts:6`, `tests/integration/setup.ts:12`, and `scripts/export-question-feedback.ts:8-9`. - The preflight predicates are written four times with two different definitions of "dummy": the two suites and the wrapper use `includes('dummy')`; `tests/e2e/helpers/seed-test-user.ts:79-81` uses `=== 'sk_test_dummy'`.

The wrapper's invocation-and-proof core should stay, and it should not be the only place the property holds. The round-3 process audit also proved its process-management branches load-bearing for the detached Vitest worker tree; step 4 moves only the nine duplicated preflight cases.

### F3 — The integration lane never discovers `.env.local`, and `.env.test` supplies an unusable fallback

`tests/integration/setup.ts:12` calls `loadDotenvFileOrThrow(resolve(__dirname, '../../.env.test'))` before any suite module evaluates. `.env.test` is committed and its line 23 sets `STRIPE_SECRET_KEY` to an `sk_test_dummy…` placeholder (14 keys total). `tests/shared/load-dotenv-file.ts:7-11` passes `override` only when explicitly requested, so dotenv's documented default applies: an already-exported variable wins; an unexported one takes the file's value ([dotenv README, "override"](https://github.com/motdotla/dotenv/blob/master/README.md)).

The precise consequence: `.env.local` holds a real `sk_test_` key (presence verified; value never printed), but only Playwright and drizzle-kit read `.env.local`. The integration lane reads `.env.test` instead, so with nothing exported the suites see the dummy and F1's second branch fires. An operator who exports the real key first gets a run — which is why the first diagnosis in this campaign ("no Vitest config loads dotenv") was wrong, and why the review's third F1 row matters: the dummy key is the common trigger, not the defect. The defect is F1; F3 is why the default local path hits it.

In CI the same mechanism is masked: `.github/workflows/ci.yml:53` exports `STRIPE_SECRET_KEY: ${{ secrets.STRIPE_SECRET_KEY || 'sk_test_dummy' }}` at job scope, which wins over `.env.test`. (The job-scope export itself is [DEBT-474](./debt-474-ci-secret-scope-and-action-immutability.md) F1.)

### F4 — The E2E skip-policy check is a latent guard defect

`.github/workflows/ci.yml:91-103` is the only executable skip policy in the repository:

```sh
violations="$(grep -nH "test\.skip(" tests/e2e/*.spec.ts \
  | grep -v "test\.skip(!hasClerkCredentials, 'Missing Clerk E2E credentials');" \
  || true)"
```

Its mechanism is brittle: it recognizes one literal form, so `describe.skip`, `test.skipIf`, `test.fixme`, `it.skip`, a reformatted allowlisted line, and any spec in a subdirectory are invisible; a grep that cannot read its inputs becomes zero violations through `|| true`; and `tests/ci-workflow.test.ts` pins other steps (`:47-82`) but not this one, so deleting it would not fail a test. It originated in [DEBT-245](../_archive/debt/debt-245-e2e-pyramid-drift-and-skip-governance.md) (`b9002c37`, 2026-02-23) after the E2E suite had silently shrunk, and DEBT-471:121 records that it "worked throughout this incident."

Scope is stated precisely because the first filing overstated it: today, every E2E skip is one of the fourteen allowlisted sites (F8), the two provider ternaries (F1) are integration files outside a step named *E2E* skip policy, and the only other skip forms in the tree are two deliberate POSIX `it.skipIf(process.platform === 'win32')` cases in the wrapper's tests. F4 is a guard that cannot detect the forms it would need to detect *next time*, not evidence of a present hidden omission. Step 2 replaces it with a parser-backed scan that resolves the test-framework receiver (`vi`, `test`, `it`, `describe` imported from `vitest` / `@playwright/test`) rather than banning every method named `skip` or `only`.

That premise is incomplete: "When a Dependabot event triggers a workflow, the only secrets available to the workflow are Dependabot secrets. GitHub Actions secrets are not available. You must therefore store any secrets that are used by a workflow triggered by Dependabot events as Dependabot secrets." ([GitHub Docs](https://docs.github.com/en/code-security/dependabot/troubleshooting-dependabot/troubleshooting-dependabot-on-github-actions)). `gh secret list --app dependabot` is empty, so this is an unsurfaced decision, not a configured one. **It is not, however, a decision this debt can make safely:** `ci.yml:35-62` places every Clerk, Stripe, and E2E credential at job scope, where dependency code executes during typecheck, unit, browser, integration, and build — not only during E2E. `pnpm-workspace.yaml:83-92` sets `strictDepBuilds: true` with an eight-entry `allowBuilds` map (four allowed, four denied), which fails the install on any unreviewed *install* script ([pnpm docs, build settings](https://pnpm.io/settings/build)); it does nothing for code that runs later. Mirroring shared credentials into the Dependabot store would hand them to exactly the code a dependency bump changes. The secret-scope fix comes first and is [DEBT-474](./debt-474-ci-secret-scope-and-action-immutability.md); this debt's step 6 waits on it.

The non-PR-time mitigation depends on the Dependabot route. Version updates target `dev` (`.github/dependabot.yml:4-7,75-78`), so the later human promotion PR and its eventual post-merge push to `main` both run the full E2E lane with CI's secrets. Security-update entries (`:54-71,97-109`) omit `target-branch`, so they open directly against the default branch and have **no promotion PR**; only the post-merge `main` workflow (`ci.yml:3-6`) runs E2E before its dependent deploy job. In both routes the changed dependency has already merged before this evidence arrives. That makes the Dependabot row more consequential than the fork row: a security PR can enter the only protected branch with a required check that never exercised E2E and never said so in the aggregate.

### F6 — The written merge bar is stronger than the enforced one

Read from the GitHub API at filing (`gh api repos/…/rulesets/17666822`; classic branch-protection endpoints return 404 for both branches):

- One active ruleset, `main-protection`, targeting `~DEFAULT_BRANCH` only, with **no bypass actors**. `dev` — the integration branch every implementation PR merges into — has no ruleset and no classic protection.
- Rules: `deletion`, `non_fast_forward`, `pull_request` with `required_approving_review_count: 0`, `required_review_thread_resolution: false`, `dismiss_stale_reviews_on_push: false`, `require_extra_approval_for_unattributed_changes: true`, and `required_status_checks` listing exactly one context, `test`, with `strict_required_status_checks_policy: false`.
- Zero required approvals is deliberate: [BUG-248](../_archive/bugs/bug-248-main-branch-has-no-github-merge-gate.md) (resolved 2026-06-14) set it "so the solo owner is not locked out."
- CodeRabbit review, Codecov, thread resolution, and the local full gate — all mandatory in `AGENTS.md`, `CLAUDE.md`, and `.claude/rules/git-workflow.md` — are process controls. CodeRabbit's `pass` context is reported but not required.

This is an enforcement inventory, not an accusation: every promotion in the DEBT-465 through DEBT-472 arc carries a CodeRabbit approval on its exact head. It records that the process is the *only* control and that "CodeRabbit review required before every merge" describes a discipline, not a gate. Whether to change that is step 7, an owner decision with its own hazards: required-check naming and path filtering were deferred for recorded reasons (`docs/dev/testing-infrastructure.md:393`), and a required CodeRabbit context is a different question from either.

### F10 — The local-run wrappers infer "CI" from an environment variable and fail open on it

Found by the toolchain census and re-read at `5a095f12`. The same defect class as F1 — a missing or misleading precondition converts into silent success — in the scripts every developer runs:

- `scripts/e2e-local-orchestrator.ts:36-42` `shouldUseIsolatedLocalE2E` returns false whenever `CI` is truthy. A developer with `CI=1` exported locally silently gets the passthrough plan; `playwright.config.ts:6-7` then loads `.env.local`, and E2E runs against the remote Neon database it names — the [DEBT-411](../_archive/debt/debt-411-local-e2e-flakiness-and-error-masking.md) incident. Unlike the integration lane (`setup.ts:61`), the E2E path has no "refuse non-local host" guard (grep of `credential-health-check.ts` and the orchestrator finds none); the only downstream mitigation is the migration-ledger check at `credential-health-check.ts:450`, which verifies the schema, not the target.
- `scripts/run-local-integration.ts:29-31` makes the same inference. With `CI=1` and no `DATABASE_URL`, Vitest runs bare, `setup.ts:12` loads `.env.test`, and the raw fixed-port fallback recorded in `.env.test:5-10` and `docker-compose.yml:13` connects to whichever container owns that port — another clone's, or none. `setup.ts:61` refuses only non-local hosts, so cross-clone contamination passes.
- `tests/integration/setup.ts:45` guards the entire preflight — URL parsing, the non-local refusal, and the `SELECT 1` — with `if (databaseUrl)`. An explicit empty value is retained because dotenv does not override an already-defined variable, so `CI=1 DATABASE_URL= pnpm test:integration tests/integration/stripe-checkout-client-contract.integration.test.ts` reaches this branch through a supported command and exits 0 with all four cases skipped.

A fourth candidate, `tests/e2e/helpers/question.ts:21-24`, was listed in the previous draft and is **withdrawn**: the `TimeoutError` it swallows is the expected outcome of a negative wait for the "Question not found" text *after* the question heading is already visible (`:72-80`), and `question.test.ts:42` pins it as non-fatal. It is an inverted check that could become an explicit race between question content and the not-found state; it is not a fail-open.

The E2E and raw-fallback branches need a stray `CI`; the empty-URL branch additionally needs an explicit empty value. All are reachable through supported commands, even though none is the clean-environment default. The correct pattern is already in the tree: explicit opt-in (`E2E_USE_EXISTING_DATABASE` at `:41` is the honest form; `CI` is not a user intent), a non-local refusal on the E2E path mirroring `setup.ts:61`, and a preflight that throws on an empty URL instead of skipping. (The plan resolution for `CI=1` was re-executed without launching E2E; it selected passthrough and resolved to the remote host `.env.local` names.)

## Impact

Ranked by consequence:

1. **Merge evidence is not what the aggregate green says it is (F5, F6).** A Dependabot security PR can reach `main` with the only required check green and the E2E lane absent, under a ruleset requiring zero approvals and no thread resolution. The absence is visible in the job's step list and nowhere else. Fork PRs additionally lose 398 browser tests that need no secret.
2. **Six live Stripe contract cases can be falsely reported green at every entry point except one (F1, F2, F3).** Those cases are the only executed proof of cardless-trial cancellation and card-present activation at trial end, frozen Checkout replay versus live retrieval, `starting_after` pagination with `has_more`, terminal-Session visibility, and same-key/different-parameter `idempotency_error` — the semantics DEBT-466/467/470 rely on. The scheduled wrapper protects the weekly cadence; nothing protects a developer who ran the obvious command and believed the result.
3. **A stray `CI=1` points local E2E at the remote database (F10).** The DEBT-411 incident class remains reachable by one environment variable.
4. **The skip policy cannot see the next skip (F4, F8).** The grep recognizes one form, and the fourteen allowlisted lines are the fail-open branch it allows.
5. **A documented six-case scheduled proof has zero hosted executions (F7).**
6. **The safe provider path costs more than the unsafe one (F2).**

## Resolution

Ordered so that each guard lands with a red test for the forbidden state (F9). Steps 1–5 are code; 6–8 are owner decisions and a convention. Step 6 is gated on [DEBT-474](./debt-474-ci-secret-scope-and-action-immutability.md).

1. **[x] Make the Stripe provider suites fail closed at module scope (completed 2026-08-26).** Extract one client-owned seam, `tests/shared/stripe-provider-gate.ts`, exporting `resolveStripeProviderGate(env, { flag, priceKeys })` that returns `{ mode: 'skip', reason }` when the flag is not `'true'` and **throws** `StripeProviderGateError` (`PROVIDER_KEY_INVALID` / `PROVIDER_PRICE_INVALID`; values never logged) when the flag is on and any prerequisite is unusable. One definition of "usable" (required prefix, at least one following character, no `dummy`), consumed by both suites, the wrapper's preflight, and `seed-test-user.ts:84`. Red-first unit cases: flag off → skip; flag on + dummy or prefix-only key → throw; flag on + usable key + dummy or prefix-only price → throw; flag on + usable inputs → run; error text contains no key material. After this step the three F1 rows exit nonzero; the flag-off run still exits 0 with the cases reported skipped.
2. **[x] Replace the grep with an executable, parser-backed skip policy, and delete the fourteen E2E skips (completed 2026-08-26).** `tests/skip-policy-source-scan.ts` walks repository TypeScript and JavaScript recursively with explicit generated/dependency exclusions. Its cooperating-author contract detects static member controls named `skip`, `skipIf`, `runIf`, `todo`, `fixme`, and `only`, plus the `cond ? describe.skip : describe` ternary. Direct `vitest` / `@playwright/test` imports are attributed precisely, direct imports from other modules are known non-framework bindings and ignored, and every unclassified receiver fails closed as a violation without alias or data-flow resolution. Receiverless aliases are outside this policy's stated threat model. The walk fails closed when unreadable or empty. Floors are **zero** E2E credential skips, the step-1 gate form in the two provider suites, and the two named POSIX `skipIf` cases in the wrapper. Red-first receipts cover a synthetic framework control, an unclassified receiver, and unreadable input. The fourteen E2E skips and former CI grep are deleted, and `tests/ci-workflow.test.ts` pins the grep's absence.
3. **[x] Make required CI evidence honest (completed 2026-08-26).** The browser install and browser test steps are unconditional (`ci.yml:91-97`). Every summarized lane has a stable `id`, and the final `Evidence summary` uses `if: ${{ !cancelled() }}`, derives all five results from `steps.<id>.outcome`, writes them to `$GITHUB_STEP_SUMMARY`, and emits `::warning::` for every omitted or unknown result (`:153-194`). The duplicate `Validate E2E credential inputs` bash step is gone; `credential-health-check.ts:80-123` through the Playwright `setup` project remains the single fail-closed E2E gate. `tests/ci-workflow.test.ts:135-214` pins the unconditional browser lane, real outcome expressions, stable ids, validator deletion, and the pending-DEBT-474 Dependabot reason.
4. **[x] Make the safe provider path the default one and give the duplicated preflight one owner (completed 2026-08-26).** Rename `scripts/run-trial-clock-smoke.ts` → `scripts/run-stripe-provider-contracts.ts` (with its two test files and the workflow reference). The dedicated entry point *is* operator intent: the wrapper no longer requires `RUN_STRIPE_TRIAL_CLOCK_SMOKE` in its own environment (the review showed the first draft's command would have failed `PREFLIGHT_FLAG_INVALID`); it loads `.env.local` with `override: false` (`scripts/run-stripe-provider-contracts.ts:71-75`), runs the step-1 gate in `run` mode, and injects both flags into the child (`:98-103`). The workflow keeps its explicit `env:` block as documentation. Add `"test:stripe-provider": "tsx scripts/run-stripe-provider-contracts.ts"`. Give the provider files a dedicated `vitest.stripe-provider.config.mts` with no database setup; the wrapper must not keep its prior `DATABASE_URL=''` workaround, because step 5 makes an empty database URL a configuration error. Move the nine preflight cases to the step-1 seam and keep the other 35 cases. The exact 44-case audit found no deletion licensed by the present design: successful exit, nonzero exit, signal exit, spawn failure, timeout, Windows direct-child termination, missing-pid fallback, POSIX group termination/fallback, parent `SIGINT` and `SIGTERM` forwarding, and escalation each cover a live branch in `spawnVitest` / `terminateVitestProcessTree`; the reporter and scratch cases prove separate failure contracts. In particular, `detached: true` on POSIX (`:250`) prevents the terminal from signaling the child group when the parent exits, and the parent's timer dies with it, so forwarding plus bounded SIGKILL escalation is what makes a foreground `pnpm test:stripe-provider` cancellation safe. The prior 19/9/16, 20/9/15, and 29/9/6 splits are withdrawn; the exact disposition is **35 keep / 9 relocate / 0 delete** unless a future implementation first removes a supported behavior and supplies an equivalent process-tree proof. `docs/dev/integration-tests.md` documents the one command and its measured `PASS executed=6 passed=6 skipped=0` receipt.
5. **[x] Make the local-run wrappers fail closed (F10) (completed 2026-08-26).** `CI` no longer grants database-target authority. With its lane-specific existing-database flag unset, each wrapper resolves the per-clone isolated target regardless of `CI`; with the flag true, it requires an explicit `DATABASE_URL`. Required CI exports `INTEGRATION_USE_EXISTING_DATABASE=true` only on integration and `E2E_USE_EXISTING_DATABASE=true` only on E2E; the hosted-Checkout workflow exports only the E2E flag (`tests/ci-workflow.test.ts:190-207`). The E2E passthrough path refuses a non-local host without `ALLOW_NON_LOCAL_DATABASE_URL=true`, integration setup throws on an empty URL, and `.env.test` contains no fallback `DATABASE_URL`. The withdrawn `question.ts` candidate was not changed: its negative wait is not a fail-open (F10).
