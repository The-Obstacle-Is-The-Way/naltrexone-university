# DEBT-217: History Back Link Loses Tab and Filter State

**Status:** Open
**Priority:** P2
**Date:** 2026-02-14

---

## Description

When a user navigates from the History page's Questions tab (with active filters) to a question detail page and clicks "Back to History," they lose both their **tab selection** and **filter state**.

### User Journey (Current)

```
1. User is on:  /app/history?tab=questions&result=incorrect
2. Clicks question link → /app/questions/slug?from=history&mode=review
3. Clicks "Back to History" → /app/history
4. Default tab is "sessions" (not "questions")
```

**Two levels of state loss:**
1. **Tab**: User was on Questions tab → lands on Sessions tab (wrong tab entirely)
2. **Filters**: `result=incorrect`, `difficulty=hard`, etc. → all gone

### Root Cause

The `getOriginUi()` function in `question-page-client.tsx` builds the back href from `ROUTES.APP_HISTORY` (bare `/app/history`) when there is no `sessionId`:

```typescript
if (resolvedOrigin === 'history') {
  return {
    backHref: sessionId
      ? `${ROUTES.APP_HISTORY}?tab=sessions`
      : ROUTES.APP_HISTORY,  // ← no tab, no filters
    backLabel: 'Back to History',
    ...
  };
}
```

And `parseHistoryTab()` defaults to `'sessions'` when no `?tab=` param is present:

```typescript
export function parseHistoryTab(value: string | undefined): HistoryTab {
  if (value === 'questions') return 'questions';
  return 'sessions';  // ← default
}
```

The question link generated by `history-questions-tab.tsx` only carries `from=history` and `mode=review` — no tab or filter context:

```typescript
const href = toQuestionRoute(row.slug, {
  from: 'history',
  mode: 'review',
});
```

### What Already Exists

The infrastructure to reconstruct a filtered history URL is already in place:
- `buildHistoryQuestionsHref()` in `history-search-params.ts` accepts `{ limit, offset, filters }` and produces a full URL with all query params
- `QuestionsFilters` type captures `difficulty`, `tagSlug`, `result`, `source`
- `toQuestionRoute()` in `routes.ts` accepts arbitrary options but currently only supports `from`, `mode`, `sessionId`, `attemptId`

## Impact

- **P2 — Medium friction**: Users lose their filter context every time they drill into a question from History. They must re-apply filters after each "Back to History" click.
- **Compounded by filter complexity**: History now supports 4 server-side filters (difficulty, tag, result, source) after DEBT-206 resolution. Losing all 4 is more painful than losing 1.
- **Tab loss is the worst part**: Landing on the wrong tab (Sessions instead of Questions) is disorienting — the user sees completely different content.

## Resolution

### Approach: Thread `historyTab` Through the Question Link

The minimal fix that preserves the tab without over-engineering:

#### Step 1: Add `historyTab` to `toQuestionRoute` Options

```typescript
// lib/routes.ts
export function toQuestionRoute(
  slug: string,
  options?: {
    from?: QuestionOrigin;
    mode?: QuestionMode;
    sessionId?: string;
    attemptId?: string;
    historyTab?: 'sessions' | 'questions';  // NEW
  },
): string {
  // ...
  if (options?.historyTab) params.set('historyTab', options.historyTab);
  // ...
}
```

#### Step 2: Pass `historyTab` from History Questions Tab

```typescript
// history-questions-tab.tsx
const href = toQuestionRoute(row.slug, {
  from: 'history',
  mode: 'review',
  historyTab: 'questions',  // NEW
});
```

#### Step 3: Reconstruct Back Href in `getOriginUi`

```typescript
// question-page-client.tsx
if (resolvedOrigin === 'history') {
  const tab = historyTab ?? (sessionId ? 'sessions' : undefined);
  return {
    backHref: tab
      ? `${ROUTES.APP_HISTORY}?tab=${tab}`
      : ROUTES.APP_HISTORY,
    backLabel: 'Back to History',
    ...
  };
}
```

### Future Enhancement: Preserve Full Filter State

Threading all 4 filters (`result`, `difficulty`, `tag`, `source`) through the question URL adds complexity. Options:

1. **Encode filters in query params**: `historyResult=incorrect&historyDifficulty=hard` — explicit but verbose
2. **Encode as base64 state blob**: `historyState=eyJ0YWIi...` — compact but opaque
3. **Use `history.back()` with link fallback**: Natural browser behavior, works for the common case

Recommend starting with just `historyTab` (Step 1-3 above) and evaluating whether full filter preservation is needed based on user feedback.
